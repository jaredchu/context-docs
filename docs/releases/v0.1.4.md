# v0.1.4 — draft experimental prerelease

Bundles **context-docs 0.1.4** and unchanged **adopt-context-docs 0.1.5**.
This release is being prepared and has not been published.

No-change maintenance now uses current documents and supplied evidence before
accessing history. Enabled logging and a link to an event do not by themselves
justify a journal read. Use known entry-point paths directly so broad file searches
do not enumerate history unnecessarily. New-event capture, targeted investigation
and checking uncertain writes remain supported; helper/schema are unchanged.

Existing project settings, adoption dates, paths and history are preserved.
Logging remains optional and project-local. There is no global-enable switch.
Review customizations and update the complete core skill folder; the existing
adoption 0.1.5 package remains compatible.

The [read-gating study](../../evals/results/2026-09-28-read-gating/README.md) retains
12 sessions and their separate harness/exposure failures. The
[global-installation acceptance check](../../evals/results/2026-09-28-global-v014/README.md)
retains five further sessions. The final candidate passes the no-access check in
Codex named invocation and explicit native Claude Skill invocation. Claude's
initial slash-only request did not load the skill, and the first explicit-tool
control still enumerated history; neither is rescored. The final two-sentence
path clarification received those two focused no-change checks; earlier capture
and investigation results remain attached to the preceding candidate's hashes.

All 90 local regression tests and container-free study controls passed; metadata
and repository static checks passed separately. These small supervised studies
do not establish reliable automatic selection, unrestricted behavior or a
logging-cost advantage. For Claude automation, verify that the skill actually
loads; the explicit native Skill invocation passed this test, while slash-only
selection remains a recorded limitation.

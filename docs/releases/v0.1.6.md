## Changes since v0.1.5

Core guidance now selects retained information by its intended readers, sharing
destination and lasting usefulness. The
[standard](../../skills/context-docs/references/standard.md#audience-and-destination)
covers public contributor docs, restricted team procedures, personal workspace
notes and mixed audiences. It preserves relevant operational constraints and
failed evidence while separating current context from detailed history and
incidental local state. Public derivatives must retain provenance and meaningful
diagnostic relationships; cleanup does not authorize discarding source evidence.
The standard adds a local working state role and applies audience selection to
optional journal payloads without enabling logging. The core guidance excludes
secrets and unnecessary personal or customer data from context. The starter
context template follows the same guidance.

Adoption now explicitly preserves existing equivalent maintenance rules as
written. Newly added wording adapts to local terminology without client-specific
invocation syntax.

Repository updates add bounded adoption and audience evaluations and clarify
future marker-format grading. The revised evaluator accepts supported fenced
markers only in future freezes; the completed adoption study keeps its original
failure and scores. The
[evidence cleanup record](../evidence-redaction-2026-10-09.md) documents normalized
public copies and unchanged historical scores; it does not sanitize older Git
history. See the [changelog](../../CHANGELOG.md) for per-change validation.

## Installation and upgrade

Follow the [installation instructions](../../README.md#install-in-codex) for the
chosen client and scope. Install or update both complete skill folders together;
adoption requires the sibling core package. Review existing files, back up local
customizations and preserve them when applying the package changes.

Existing projects need no directory or document migration. Preserve their loaded
maintenance rules, adoption dates, entry paths and logging settings. Installing
or updating the skills does not enable logging. The existing opt-in auto preference
and explicit-setting precedence remain unchanged, as do the journal helper and
schema. Ordinary Markdown maintenance has no runtime dependency; the optional
helper requires Python 3.9+, and auto detection also requires Git.

The [October 9 public-source adoption regression](../../evals/results/2026-10-09-public-adoption/README.md)
ran four native Claude Opus 5.5 sessions with core 0.1.5 and adoption 0.1.7.
Execution passed **4/4**; frozen mechanical checks passed **3/4**, retaining the

in all four sessions. Full-claim semantic acceptance remained **Astra 1/4 versus

The [October 10 audience/destination pilot](../../evals/results/2026-10-10-audience/README.md)
used this package bundle in five native Claude Opus 5.5 sessions.
Execution passed **5/5**. GPT 6 Astra High and Claude Opus 5.5 each accepted
**19/19 target criteria** and **15/15 general criteria**. The mixed case completed
its API documentation edit and asked the permitted audience/destination question;
it **did not produce a handoff artifact**. The audit attempted no writes or
history access. Neither study retried subjects or repaired their outputs.

Mechanical checks are separate from actual agent evaluations. These small,
authored studies used explicit invocation and restricted tools on one client and
responding model, with unblinded counterpart review. They establish neither
general reliability nor comparative benefit, automatic skill selection or
unrestricted-client behavior. Earlier factual, invocation and journal-access
limitations remain recorded in the linked reports and
[project context](../project-context.md#evidence-and-limits).

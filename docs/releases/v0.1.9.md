# v0.1.9: experimental prerelease

Release date: October 11, 2026. Bundles **context-docs 0.1.9**,
**adopt-context-docs 0.1.9** and **standard 0.1.1**.
[GitHub prerelease](https://github.com/jaredchu/context-docs/releases/tag/v0.1.9).

## Changes since v0.1.8

When creating context from earlier notes, the core skill now explicitly asks the
agent to check relevant project sources before importing claims about current
implementation or configuration. Decisions, rationale and unfinished work still
carry forward. The adoption skill inherits this guidance through its sibling core;
its package and the standard are unchanged.

This addresses an observed adoption failure: old notes reported a 10-second
timeout even though the configuration set 20. The new guidance makes that source
check explicit during initialization. Configuration alone still does not establish
runtime or deployed behavior, and the skill does not guarantee factual accuracy.

The website explains source checks during setup while retaining the
existing guidance that normal maintenance needs no repeated skill invocation.
Both pages show experimental/released status and SEO titles without em
dashes. The build still publishes only its nine explicitly allowed public files.

## Installation and upgrade

Follow the [upgrade guide](../getting-started.md#upgrading). Review installed files
and preserve local customizations when updating complete sibling skill folders.
No project re-adoption or document migration is needed for this guidance change.
Existing maintenance rules, adoption dates, context paths, ignore rules, logging
settings and event history stay in place. Installing an update does not select
local-only storage or enable logging. A previously selected `auto` preference
can still resolve during later authorized setup or maintenance under its existing
rules; every explicit project logging setting wins.

This release does not update installed skills or project setups.

## Validation and limits

The [focused source-selection record](../../evals/source-selection/README.md)
retains two baseline and two candidate source-selection attempts plus an earlier
sandbox-blocked setup attempt. One baseline kept the stale 10-second claim; the
other correctly used 20. Both candidate attempts used 20 from the configuration,
distinguished the old claim, and preserved approved rationale, the dataset blocker
and next step, and the local-only sharing boundary. The blocked attempt produced
no context; its unused companion fixture was not executed.

These author-created trials invoked supplied skills directly. GPT 6.1 Sol was
requested with medium effort; its responding identity was not independently
confirmed. Claude Opus 5.5 reviewed the fix and evidence. The mixed baseline and
small fixture establish no causal accuracy advantage or general reliability,
privacy, implicit-selection, instruction-loading or user-effort benefit. Literal
canary checks require separate semantic and transcript inspection.

The fix commit [45bc88f](https://github.com/jaredchu/context-docs/commit/45bc88f756dcf6b76abba69bd9df8b29c4e543f4)
passed [static checks](https://github.com/jaredchu/context-docs/actions/runs/38069028575)
and [landing-page checks](https://github.com/jaredchu/context-docs/actions/runs/38069028597).
Those runs precede this release-preparation diff. The
[preparation record](v0.1.9-validation.json) separates package identities, earlier
native evidence, local preparation checks and publication evidence. Saved study
artifacts, previous release records and existing setups are preserved.

Release preparation runs 59 local unit tests, repository static checks and the
public website build, with desktop/mobile previews. These checks are separate
from the earlier native trials; no new subject sessions are run. The

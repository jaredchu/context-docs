## What changes

A progress visualization now asks for a compact text tree, arrow path or nested
Markdown checklist that shows how the work contributes to the documented goal.
A flat status table alone is insufficient.

- Branch parallel completion conditions; show ordering only when supported.
- Put each blocker beside the work it stops, with its prerequisite and next action.
- Keep unapproved proposals outside the required completion path and mark unknowns.
- Link each item and relationship to its source. Keys inside a fenced diagram
  need real clickable Markdown links outside it.

The [synthetic example](../../examples/progress.md) shows one passed check and
one blocked check, with the missing input and next step nested beneath it.
Markdown remains authoritative; no viewer, tracker or runtime is added to the
skills. The website preparation displays that same canonical example on both
public pages and retains SEO titles without em dashes.

## Existing projects and upgrades

Ordinary maintenance preserves an existing view's format. An explicit
visualization request can reshape that view within its existing section or file,
preserving owner edits and record locations. Once a visual path exists, authorized
maintenance refreshes it from relevant new facts; an identical repeat makes no edits.

No re-adoption or document migration is required. Existing maintenance rules,
adoption dates, context paths, local-only boundaries, ignore rules, logging
settings and saved history stay in place. Audits remain read-only.

Installed v0.2.0 skills retain their earlier guidance until separately upgraded.
Follow the [upgrade guide](../getting-started.md#upgrading), preserving local
customizations and complete packages. Adoption 0.1.10 already routes to its sibling
core; its package and the standard are unchanged. Release preparation does not
upgrade installations or alter project setups.

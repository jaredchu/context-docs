# v0.2.7: simplify instructions and clarify installation

**Experimental prerelease, November 7, 2026.**
Bundle: **context-docs 0.2.7**, **adopt-context-docs 0.1.16** and unchanged
**standard 0.1.1**. Previous bundle: [v0.2.6](v0.2.6.md).
Publication and installation are separate actions. The owner separately authorized website deployment; installed upgrades remain separate.

## What changes

The core skill consolidates the canonical-location rule and removes an incidental
ASD-STE100 example. Adoption shortens repeated coordination, storage and setup
instructions while continuing to require the sibling core skill. The release
retains the existing clarity, preservation, audience, scope, progress, logging,
shared-file coordination and publication safeguards. It adds no background service,
file synchronization, storage migration or new runtime dependency.

The accompanying documentation:

- Pins everyday installations to published v0.2.7 (core 0.2.7 and adoption 0.1.16),
  verifies the expected versions and labels development-source installation separately.
- Links newer feedback and focused studies from the [evidence overview](../evaluation-results.md#more-recent-studies),
  preserving each record's versions, method, outcomes and limitations.
- Reminds users to transfer shared context alongside code within an already-authorized
  Git workflow and check the destination checkout before resuming. Ignored local-only
  context needs an existing private transfer or backup procedure.
- Keeps public contributor context focused on the project and its readers.
  Actual model provenance, attribution and frozen evidence remain intact.

## Existing projects and upgrades

Publication and installation are separate actions. Existing installations keep their
current guidance until separately upgraded. Preserve customizations and both complete
sibling packages; follow the [upgrade guide](../getting-started.md#upgrading).
Keep context locations, layouts, decisions and rationale, maintenance rules,
adoption dates, local-only boundaries and logging settings. Publication
does not authorize moving records or rewriting historical evidence. Audits remain read-only.

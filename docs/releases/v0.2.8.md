# v0.2.8 candidate

Prepared 21 November 2026 from source `9509321`. The candidate bundles
**Context Docs 0.2.8** and **Adopt Context Docs 0.1.16**. Everyday
installation still selects the published [v0.2.7 bundle](v0.2.7.md).

## Changes

- When Codex and Claude Code share a context file, agree on the current
  writer and hand off ownership explicitly. Identify the checkout and
  affected paths, release those paths before the next writer starts, and
  reread the file before editing. Keep private context and journal payloads
  out of the handoff.
- Send optional journal events through standard input. When a payload
  needs a file, use an authorized private scratch path outside the
  checkout and journal directory.
- Keep the site badge tied to the source release status. While core 0.2.8
  is unreleased, the site identifies it as such alongside the published
  v0.2.7 install instructions.

The bundle includes the existing
[adoption skill 0.1.16](../../skills/adopt-context-docs/SKILL.md). The
[usage guide](../getting-started.md) covers installation and upgrades for
existing projects.

## Candidate checks

An offline, project-scoped install with `skills 1.7.4` copied
both skills into the Codex and Claude Code project directories. All
16 tracked package files matched the candidate byte for byte in each
layout. The package versions were 0.2.8 and 0.1.16. The installed journal
helper appended a synthetic stdin event and read it back in each layout.
This checks packaging, local placement, and the journal helper.

Repository static checks, the journal and site tests, and a local site
build passed. Runtime skill discovery and model behavior during a writer
handoff remain unverified.

## Publication and upgrades

Keep public install instructions on the published bundle until the new
tag is available. After publication is authorized, validate the exact release
commit, coordinate the install-pin switch, and follow the
[release checklist](../../CONTRIBUTING.md#release-checklist) for the separate
skills.sh refresh and page verification. Existing users can follow the
[upgrade guide](../getting-started.md#upgrading) when they choose to install
a published update.

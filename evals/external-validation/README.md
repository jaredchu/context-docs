## Two ways to contribute

- **Suggest a case:** copy [case-proposal.md](case-proposal.md), name a public
  documentation-maintenance event you encountered, and supply source links.
  Select it before reading our skill, protocols or results where possible. You
  do not need to design an experiment, run a model, install Python or pay for a
  subscription. Leave technical pinning and execution to the coordinator.
- **Review an artifact:** use [review-template.md](review-template.md) with the
  coordinator's source packet. Check factual support and useful preservation;
  model subscriptions and code execution are unnecessary.

Submit a proposal or request a review packet through a
[GitHub issue](https://github.com/jaredchu/context-docs/issues) or a pull request.
Submit initial reviews there before receiving the condition mapping; the
coordinator records receipt, then unmasks. Submissions are public: avoid reading
other proposals, reviews or labeled results before your selection/initial review,
and disclose anything already seen. No contact or submission is automatic.

Use public, appropriately licensed material only. Do not submit private project
context, credentials or personal operational details. A source being public does
not itself establish permission to redistribute it. Link to upstream material
and retain its license/attribution; record permission for any supplied excerpts.
Contributed template text follows this repository's [contribution terms](../../CONTRIBUTING.md).

relationships, exposure and revisions. Report **case selection, ledger authorship
and review independence separately**, including pending contributor confirmation.
Exposure limits clean-room claims without making the input useless.

Take at most **two eligible nominations** initially: one pilot and one reserved
holdout. Record receipt order; use the first eligible nomination as pilot and the
second as holdout. Eligibility means public/licensed, bounded, source-verifiable,
and a plausible maintenance need within the existing layout. Record rejected
nominations and reasons; do not select for an expected winning method. If only
one qualifies, report that there is no holdout. Do not invent a second case.
Initially reserve only the holdout nomination and source revision; do not build
its ledger or use it in skill/protocol tuning. Freeze post-pilot methodology and
skill first, then prepare its detailed ledger before a separate execution freeze.
Record preparation exposure. Neither two cases nor external selection establishes
generality.

## Coordinator checklist before any new execution

1. Preserve the original nomination and exposure declaration. Confirm the task
   with its contributor; retain every substantive author revision and attribution.
2. Pin public source URLs to revisions, record source dates, license, file modes
   and content hashes, and inventory the complete shared evidence. Prefer complete
   repository snapshots; declare any omissions and historical coverage limits.
3. Keep the **entire proposal evaluator-only**, including its ledger. Subjects
   receive the frozen task, write boundary and pinned corpus, plus declared
   treatment. Derive criteria from that readable source evidence; exclude proposal,
   answer key, controls and reviewer notes from subject access. Ask the contributor
   to confirm the maintenance need and ledger relevance; attribute ledger authorship.
4. Freeze matched ordinary/skill prompts, released package version/hash, model and
   client, skill delivery mode (explicit read/native invocation/discovery), catalog
   state, tool/write limits, budgets, order and one attempt per arm in a new
   manifest. Preserve upstream layout and loaded instructions equally; disclose
   conflicts or overrides. Vary only declared treatment. Verify actual exposure
   and isolation. This packet does not start sessions or authorize publication.
5. Before execution, check a supported answer, plausible overclaim and justified
   unknown against the ledger. Preserve evaluator repairs with old/new text,
   source evidence, author and time. A material post-freeze change requires a new
   identified freeze; never replace a failed run or silently rescore it.

## Review and reporting

The coordinator shuffles outputs, substitutes neutral artifact IDs, and withholds
condition/model labels and the mapping until initial reviews are recorded. Give
reviewers the shared task/scope, evaluator ledger and **full shared source corpus**,
including files subjects did not read. Provide final responses and diffs as well
as documents; withhold tool/read traces until initial assessments are recorded.
Neutral scope-check summaries can precede unmasking. Keep immutable originals and
disclose masking transformations; do not remove substantive revealing claims.

Ask reviewers to assess artifacts individually before comparison. Preserve their
initial judgments, source citations, exposure declarations and uncertainties,
then unmask. Resolve disputes by source inspection in a separate resolution log;
retain disagreement and original scores. Seeing the skill before or during review
is disclosed, not treated as impossible. Condition masking cannot guarantee
blindness when wording, paths or prior knowledge reveal treatment.

The four existing [HTTPX/ripgrep artifacts](../results/2026-10-10-public-history/README.md)
can receive **supplemental external review**. Those study records contain condition
labels; reading them defeats masking and must be disclosed. Prospective reviewers
should request a masked packet before opening them. They remain author-selected:
do not describe that review as independent case selection, a retry, or a replacement score.
Keep their frozen inputs, artifacts and original assessments unchanged.

Report selection, criteria authorship and review independence, with actual contributors,
models, exposure, exclusions and limitations. Report execution, mechanical checks,
required-fact retention and unsupported additional claims separately. Do not
infer reader benefit, superiority or equivalence from this small sample. No
outreach, submission, publication or recurring work occurs automatically.

# Preview design — contributor Dev, September 21
The next iteration should support --limit N for compact previews. I suggest
sorting records by id to stabilize screenshots, then taking N rows. We can stop
reading input as soon as N qualifying rows are found; preview users will probably
not care about later corrupt rows. This should reduce latency for large files.
The existing full loader is simple but reads more than the preview needs.
I also suggest merging tenant-specific queues eventually. These are design ideas
for review; no implementation has changed yet.

ABOUT THE SWITCHING WALKTHROUGHS

Hand off through files, not chat.

Both directions use the existing Reading Queue app and the same feature, split at the same point. The first client implements and tests the JSON export API, records what is complete and what is pending, and stops. A fresh session in the other client reads the saved project context, checks it against the current files and continues with the browser button.

The receiving prompt does not repeat the feature scope. The point is to see whether the saved files carry it: the requirement, the reason for exporting the whole queue, the API work that is done, the browser work that is not, and what the checks do and do not cover.

Only project files carry over. Chat history, native memory such as Claude Code auto memory or Codex memories, and the other client’s runtime state do not. Keep one writer at a time: stop the first client before the second starts. There is no sync, file locking or exclusive ownership.

Install the two Context Docs skills in each client first; see the installation guide. New to the workflow? Reading Queue introduces each step more slowly.

These are authored walkthroughs. Any observed checks of them are described, with their scope and limits, in the switching examples record. They do not establish general reliability or time or token savings.

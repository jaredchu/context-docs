THE WORKFLOW

Keep the useful parts
of the work you already do.

Context Docs is a pair of reusable instruction skills for your agent. You stay in your project, with documents you can read and edit.

  1. 01

    Set it up once

    The adoption skill uses your existing docs and adds or reuses a maintenance rule in project instructions. When starting from older notes, it asks the agent to check current-state claims against relevant project sources and preserve decisions and unfinished work. Configuration alone does not prove runtime behavior.

  2. 02

    Save what changed

    The loaded project maintenance rule guides updates after meaningful work. Review the diff: decisions, blockers and next steps should stay clear. Ask for an update if one is missed.

  3. 03

    Give the next session a starting point

    Ask the agent to read the saved context and the linked details relevant to its task. A file alone does not guarantee it will be read.

The v0.2.4 release adds a small clarity preference during authorized context edits: use clear, direct sentences and consistent project terms while preserving conditions, uncertainty, rationale and evidence. Keep existing layouts and unrelated owner text. ASD-STE100 compliance is not required.

Both clients pass the focused Markdown checks. Claude's chat report adds an unsupported pronoun; the saved Markdown is unaffected. These guided, author-scored cases do not demonstrate comprehension gains or automatic everyday application. Read the qualified clarity smoke results.

The v0.2.5 release adds conditional guidance for concurrent sessions editing the same context file: agree on one writer before edits begin, send other participants' findings to that writer, and change writers through an explicit handoff. Prefer narrow edits; after a conflict or stale-text failure, reread the current file and reconcile changes before retrying. Installing skills in both Codex and Claude does not coordinate sessions. There is no file locking or automatic merge guarantee.

In the guided candidate smoke, both clients respect ownership and handoff and reread after the forced stale edit. Claude retries its own second mismatch without another reread, a procedural failure despite preserved final content. Codex corrects a read-only anchor-check error. These author-scored cases do not test simultaneous writers or establish general conflict prevention. Read the qualified concurrency smoke results.

The v0.2.6 release strengthens what gets saved: omit incidental personal metadata from shared additions, prefer repository-relative source links and summarize useful findings instead of repeating bookkeeping. Keep useful local paths and necessary diagnostic relationships in appropriate destinations. Preserve decisions, rationale, conditions, uncertainty and evidence. Review what you share; no automatic redaction or secret scanner is included.

Both clients pass visible saved-Markdown checks in the guided, author-scored smoke. Claude could not locate an unlinked private operator note with its restricted tools; filtering incoming content from that note remains untested. These cases establish no automatic everyday application or general privacy guarantee, and native journal capture was not tested. Read the qualified metadata-filtering smoke results.

During adoption, the new guidance asks your agent to start a simple inline progress path by default when your documented goal and work support one. Keep an existing view in its current location and format. If the context is too sparse, skip the new view.

During everyday work, the loaded maintenance rule guides updates to the same view after meaningful changes; you do not need to ask each time. Keep details authoritative in one place and link to evidence instead of maintaining duplicate task lists. There is no background tracking.

Put blockers beside the work they stop. Keep ordering supported, proposals outside required work and sources clickable outside text diagrams. An explicit visualization request can reshape an existing view; ordinary maintenance preserves its format.

An explicit re-adoption may add a missing supported view while preserving setup rules and the original adoption date. Installation or upgrade alone does not change project context. Requests to omit a view or use a separate file take precedence.

An attempt can produce useful learning without completing an outcome. Possible stalls need relevant history; a saved status does not establish live activity.

CONTEXT WITH BOUNDARIES

Useful to the next reader.
Appropriate for the project.

Keep it focused

The skill asks your agent to replace stale facts, consolidate repetition and link to detailed evidence. It does not need a transcript of every session.

Respect the destination

Keep shared project docs or choose local-only context excluded from Git. The agent checks tracking and ignore rules and keeps local content out of shared docs.

Keep control

You review ordinary Markdown changes. There is no background sync or automatic publishing. Optional event logging is separate from current context.

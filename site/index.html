Context Docs helps your AI coding agent keep a short Markdown note in your project: what changed, why it was decided and what to do next. Start your next session by asking it to read that note.

Vibe coding with AI prompts? Start with one useful note or keep your existing PRD, design and task files. Review the context updates as you build, then ask your next session to read them.

02 How it works

Three small habits.
No new system.

Context Docs is two installable skills: reusable instructions for Codex or Claude Code. Your notes stay as ordinary Markdown that you can read and edit.

  1. 01

    Set it up once

    Install the skills, then run the setup skill in your project. It reuses your existing docs and adds a short maintenance rule to the instructions your agent loads. Check that the rule is actually loaded.

  2. 02

    Review useful updates

    The loaded rule guides the agent to update the note after meaningful work during active sessions. Review the diff like any other change. If an update is missed, ask for one.

  3. 03

    Read the notes next time

    Start a new session by asking the agent to read the saved file. A saved file alone does not make a new session read it.

No background service, automatic memory or sync: the agent works only during your sessions, and you review what it writes. See the limits.

06 Context with boundaries

Useful to the next reader.
Appropriate for the project.

Keep it focused

The skill asks your agent to replace stale facts, consolidate repetition and link to detailed evidence. It does not need a transcript of every session.

Respect the destination

Keep shared project docs or choose local-only context excluded from Git. The agent checks tracking and ignore rules and keeps local content out of shared docs.

Keep control

You review ordinary Markdown changes. There is no background sync or automatic publishing. Optional event logging is separate from current context.

07 Do you need another tool?

Start with the workflow you already have.

Codex and Claude Code already provide instructions and memory, and both can maintain Markdown. Context Docs is an optional starting workflow for people without an established way to preserve project decisions, current work and handoffs. If your existing practice works, you may not need it.

EXPERIMENTAL

Useful guidance.
Honest limits.

Context Docs guides an agent during active sessions; it is not automatic memory, synchronization or a background service, and it does not guarantee accuracy, privacy, smaller documents or lower token usage. Review each diff, consequential claims and what you share.

Focused checks do not establish broad reliability, privacy guarantees or effort savings. Recorded studies do not yet establish effort savings for the intended users or a skill-specific correctness advantage. There is no automatic redaction, secret scanner, file locking or merge guarantee; when sessions share a context file, agree on one writer.

Daily use and concrete feedback help us find what needs improving.
